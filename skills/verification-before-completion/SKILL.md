# Верификация до завершения

## Обзор

Заявлять что работа завершена без верификации — это нечестность, а не эффективность.

**Главный принцип:** Сначала доказательства, потом утверждения. Всегда.

**Нарушение буквы этого правила — это нарушение его духа.**

## Железный закон

```
НЕТ ЗАЯВЛЕНИЙ О ЗАВЕРШЕНИИ БЕЗ СВЕЖИХ ДОКАЗАТЕЛЬСТВ ВЕРИФИКАЦИИ
```

Если не запустил верификационную команду в этом сообщении — нельзя утверждать что она проходит.

## Функция гейта

```
ДО заявления о любом статусе или выражения удовлетворения:

1. ОПРЕДЕЛИ: Какая команда доказывает это утверждение?
2. ЗАПУСТИ: Выполни ПОЛНУЮ команду (свежую, полную)
3. ПРОЧИТАЙ: Полный вывод, проверь код выхода, посчитай ошибки
4. ПРОВЕРЬ: Подтверждает ли вывод утверждение?
   - Если НЕТ: Укажи реальный статус с доказательствами
   - Если ДА: Сделай утверждение С доказательствами
5. ТОЛЬКО ПОТОМ: Делай утверждение

Пропуск любого шага = ложь, а не верификация
```

## Типичные провалы

| Утверждение | Требует | Недостаточно |
|-------------|---------|--------------|
| Тесты проходят | команду тестов проекта (см. `CLAUDE.md`): 0 ошибок | Предыдущий запуск, «должно пройти» |
| Линтер доволен | команду линтера проекта: нет ошибок | «Я следил за стилем» |
| Эндпоинт/команда работает | реальный вызов (curl/CLI/клиент) с ожидаемым результатом | Код изменён, предполагается рабочим |
| Баг исправлен | Тест воспроизводящий исходный симптом: проходит | Код изменён, предполагается исправленным |
| Требования выполнены | Чеклист по каждому пункту плана | Тесты проходят |

## Предотвращение рационализации

| Отговорка | Реальность |
|-----------|------------|
| «Должно работать теперь» | ЗАПУСТИ верификацию |
| «Я уверен» | Уверенность ≠ доказательство |
| «Только в этот раз» | Исключений нет |
| «Частичная проверка достаточна» | Частичная ничего не доказывает |
| «Я устал» | Усталость ≠ оправдание |
| «Другими словами, правило не применяется» | Дух важнее буквы |

## Ключевые паттерны

**Тесты:**
```
✅ [Запустить команду тестов] [Видим: 34/34 прошли] → «Все тесты проходят»
❌ «Должно пройти теперь» / «Выглядит правильно»
```

**Линтер:**
```
✅ [Запустить команду линтера] [нет ошибок] → «Код проходит линтер»
❌ «Я следил за стилем, должно пройти»
```

**Требования:**
```
✅ Перечитай план → создай чеклист → проверь каждый пункт → доложи о пробелах или завершении
❌ «Тесты проходят, задача выполнена»
```

## Красные флаги — СТОП

- Использование «должно», «наверное», «похоже»
- Выражение удовлетворения до верификации («Готово!», «Отлично!», «Сделано!» и т.д.)
- Переход к следующей задаче без верификации текущей
- Доверие частичной проверке
- Мысль «только в этот раз»
- Устал и хочешь завершить
- **ЛЮБАЯ формулировка подразумевающая успех без запуска верификации**

## Когда применять

**ВСЕГДА до:**
- Любого варианта заявлений об успехе/завершении
- Любого выражения удовлетворения
- Любого положительного утверждения о состоянии работы
- Перехода к следующей задаче
- Делегирования следующему агенту

**Правило применяется к:**
- Точным фразам
- Перефразировкам и синонимам
- Подразумеваниям успеха
- ЛЮБОЙ коммуникации подразумевающей завершение/корректность

## Итог

**Никаких срезаний углов при верификации.**

Запусти команду. Прочитай вывод. ПОТОМ делай утверждение.

Это не обсуждается.
