# Генерация промпта для следующего этапа

Пользователь работает по трёхэтапному процессу и очищает контекстное окно между этапами.
Твоя задача — найти артефакт текущего этапа и написать готовый промпт для следующего.

## Маршруты

| Завершённый этап | Артефакт | Следующий этап |
|---|---|---|
| `brainstorming` | `docs/specs/YYYY-MM-DD-*.md` | `writing-plans` |
| `writing-plans` | `docs/plans/YYYY-MM-DD-*.md` | `executing-plans` |

## Процесс

### Шаг 1: Найти артефакт

Проверь оба места:

```bash
ls -t docs/specs/ 2>/dev/null | head -5
ls -t docs/plans/ 2>/dev/null | head -5
```

Правило определения следующего этапа:
- **Есть спек, нет плана** → следующий этап `writing-plans`, читай спек
- **Есть спек И план** → следующий этап `executing-plans`, читай план
- **Непонятно** — спроси пользователь какой файл использовать

Если файлов несколько — бери самый свежий (по дате в имени или `mtime`).
Если пользователь сам назвал файл — используй его без вопросов.

### Шаг 2: Собрать промпт

Используй шаблон для нужного перехода (ниже). Промпт должен работать в пустом контекстном окне без каких-либо предыдущих договорённостей.

### Шаг 3: Вывести результат

Выведи промпт в блоке кода (тройные бэктики без языка) — чтобы пользователь мог скопировать одним кликом.
После блока — одно предложение: что за файл и какой следующий этап.

## Чего не делать

- Не вставляй содержимое файла в промпт — только `@`-ссылку
- Не добавляй в промпт объяснения "для пользователя" — промпт адресован агенту
- Не вызывай сам следующий скилл — только генерируй промпт
