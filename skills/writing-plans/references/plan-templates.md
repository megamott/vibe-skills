# Шаблоны плана реализации

## Заголовок документа плана

```markdown
# План реализации: [Название фичи]

> **Для агентов:** Используй скилл executing-plans для реализации этого плана задача за задачей. Шаги используют синтаксис чекбоксов (`- [ ]`) для отслеживания.

**Цель:** [Одно предложение описывающее что это строит]

**Архитектура:** [2-3 предложения о подходе]

**Ключевые файлы / стек:** [Основные технологии/конфиги — берётся из CLAUDE.md проекта]

---
```

## Структура задачи (TDD-шаги)

Универсальный шаблон. Подставь язык и команды своего стека (см. `CLAUDE.md`, раздел «Тестирование»).

````markdown
### Задача N: [Название компонента]

**Файлы:**
- Создать: `точный/путь/к/файлу.<ext>`
- Изменить: `точный/путь/к/существующему.<ext>`
- Тест: `точный/путь/к/тесту.<ext>`

- [ ] **Шаг 1: Написать падающий тест**

```<lang>
<реальный код теста, проверяющий конкретное поведение>
```

- [ ] **Шаг 2: Запустить тест и убедиться что он падает**

Запуск: `<команда теста из CLAUDE.md>`
Ожидается: FAIL с конкретным сообщением (например, «функция не определена»)

- [ ] **Шаг 3: Написать минимальную реализацию**

```<lang>
<реальный код реализации>
```

- [ ] **Шаг 4: Запустить тест и убедиться что он проходит**

Запуск: `<команда теста>`
Ожидается: PASS

- [ ] **Шаг 5: Убедиться что все тесты проходят**

Запуск: `<команда всех тестов из CLAUDE.md>`
Ожидается: всё зелёное
````

## Пример конкретизации (Python + pytest)

````markdown
- [ ] **Шаг 2: Запустить тест и убедиться что он падает**

Запуск: `pytest tests/path/to/test.py::test_name -v`
Ожидается: FAIL
````

## Пример конкретизации (TypeScript + vitest)

````markdown
- [ ] **Шаг 2: Запустить тест и убедиться что он падает**

Запуск: `npx vitest run tests/path/to/test.spec.ts -t "test name"`
Ожидается: FAIL
````
