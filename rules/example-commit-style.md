# Формат коммитов (пример)

> Это пример. Замени префиксы и регексп под соглашения своего проекта.

## Формат сообщения

```
<type>(<ticket>): краткое описание на английском языке
```

Где:
- `<type>` — тип изменения: `feat` (по умолчанию для новой функциональности), `fix` (явное исправление бага). При необходимости добавь свой набор: `chore`, `refactor`, `docs`, `test`, `style`, `perf`.
- `<ticket>` — идентификатор задачи в трекере. Пример: `PRTL-1234`, `JIRA-42`, `#123`.
- Описание — на английском, до 72 символов, в повелительном наклонении (`add`, `fix`, `update`).

## Где взять номер задачи

Из имени ветки. Регексп для извлечения (под формат `PRTL-XXXX`):

```
[A-Z]+-[0-9]+
```

Команда:
```bash
git branch --show-current | grep -oE '[A-Z]+-[0-9]+' | head -1
```

Если в имени ветки номера нет — сообщи пользователю и используй `<ticket>` как плейсхолдер.

## Примеры

```
feat(PRTL-1234): add full-text search to articles
fix(PRTL-5678): correct pagination offset for empty results
```

## Что НЕ пишем

- Не пишем русский текст в самом сообщении коммита — только английский.
- Не пишем длинные многострочные сообщения без необходимости.
- Не дублируем тип в описании: `feat: add new feature` — плохо, `feat: support custom analyzers` — хорошо.
