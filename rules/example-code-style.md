# Код-стайл проекта Search

## SOLID

- **SRP**: класс имеет одну причину для изменений; зависимости передаются через конструктор (DI), не создаются внутри
- **OCP**: расширение без переписывания — маппинги, Strategy, полиморфизм вместо цепочек `if-elif`
- **LSP**: 100% аннотации типов; `typing.Protocol` вместо базовых классов; никаких `raise NotImplementedError` в подклассах
- **ISP**: маленькие специализированные интерфейсы; никаких методов-заглушек
- **DIP**: зависимости от абстракций (`typing.Protocol`); DI-контейнер that-depends; зависимости через `__init__`

## Архитектура

- Clean Architecture: API → Core → Infrastructure; зависимости направлены внутрь
- CQRS: команды для записи, запросы для чтения, медиатор (`search/mediator.py`)
- Repository Pattern для доступа к данным
- Порты и адаптеры

## Tooling

- Длина строки: **120 символов**
- Ruff: `select = ["ALL"]`, исключения:
  - EM / TRY003 — строки в исключениях нормальны
  - FBT — boolean-аргументы допустимы
  - D1 / D203 / D213 — принудительные докстринги без разбора → «капитан очевидность»
  - FA — не поддерживаем старые версии Python
  - COM812 / ISC001 — несовместимы с ruff format
- isort: `lines-after-imports = 2`, `no-lines-before = ["standard-library", "local-folder"]`

## Типизация и неизменяемость

- Все переменные аннотировать `typing.Final` (используется auto-typing-final)
- Все классы по умолчанию `@typing.final`
- Словари-константы оборачивать в `types.MappingProxyType`
- Строгий MyPy-режим, 100% покрытие аннотациями типов
- Не аннотировать скалярные типы явно — mypy выведет сам: `some_var = 'hello'`, не `some_var: str = 'hello'`
- TypedDict для типизированных константных словарей вместо plain `dict`

## Исключения

- Не использовать `except Exception` — максимально конкретный класс ошибки
- Минимум строк между `try` и `except` (в идеале одна)
- Предпочитать проверку условия (`if key in dict`) вместо ловли исключения
- Исключения — для исключительных случаев, не для обычного flow
- Безопасный доступ к коллекциям: `item.get("key")` для словарей; `LookupError` → `KeyError` / `IndexError`

## Retry / Resilience

- Библиотека stamina для ретраев
- Обязательно для: SQL-запросов, файловых операций, HTTP-запросов, работы с очередями
- Ограничивать количество попыток, рандомизировать интервалы
- При высокой нагрузке — circuit breaker: `circuit-breaker-box`

## Именование

- Имена переменных и функций — минимум 8 символов; запрещены `a`, `b`, `data`, `user`
- Конкретные имена с семантикой: `public_user` вместо `user`
- Функции — глаголы; существительные только для `@property`
- Без префикса `get` — использовать `fetch`, `retrieve`, `build`, `create`, `make`, `prepare`

## Импорты

- Встроенные библиотеки импортируются целиком: `import os`, `import typing` (не `from os import path`)
- Если из модуля импортируется более 2 сущностей — модуль импортируется целиком

## Классы и структура

- Композиция > наследование; не строить больших иерархий
- dataclasses: `@dataclasses.dataclass(kw_only=True, slots=True, frozen=True)`
- Инверсия условий для уменьшения вложенности (early return)
- Обработка ошибок через Result-тип вместо исключений где уместно

## Запрещённые практики

- Магия: `hasattr`, `getattr` и подобное неявное поведение
- Временные переменные без причины — только если имя добавляет смысл или значение переиспользуется
- Комментарии без необходимости — только для сложного неявного поведения
- Регулярные выражения без проверки на ReDoS-уязвимости

## Специфика проекта

- **Litestar** (не FastAPI) для HTTP API
- **OpenSearch** для полнотекстового и гибридного поиска (только read-path, без индексации)
- **PostgreSQL** для хранения истории поиска и источников
- **Cohere** для ранжирования RAG-контекста
- **that-depends** как DI-контейнер
- **stamina** для retry-логики
- **structlog** для структурированного логирования
- **pathlib** для файловых операций (не `os.path`)
